# Offer 求职助手

帮助用户完成找工作的核心环节：找岗位、维护投递追踪文档、简历分析、岗位分析。投递动作由用户自己执行，本 skill 不代替投递。

## 调用约定

- 数据文件路径由用户在每次调用时告知，不预设、不硬编码任何路径。开始工作前先向用户确认：简历文件路径、投递追踪表路径及文件格式。
- 信息查询的浏览器选择统一遵循本文件：优先使用 agent 工具支持的浏览器（如应用内浏览器、Chrome 控制）；若不可用，则使用 Edge 浏览器。优先一手来源（公司官网、官方招聘页、监管或官方公告、权威平台），输出时标注来源与查询日期；来源冲突时说明差异并给出更可信的判断。
- 处理用户文件前先读取其结构（表头、格式），理解后再操作，保留原有结构。

## 核心流程

1. **找岗位**：确认求职目标（岗位方向、城市、公司类型、薪资范围等），结合简历背景检索招聘渠道和公司官网（浏览器按调用约定选择），输出候选岗位清单。详见 [job-search.md](references/job-search.md)。
2. **维护投递追踪文档**：只有用户明确告知已投递的岗位才维护到追踪表；根据用户报告的投递、面试、结果等动作更新，只记录和维护，不代用户投递。详见 [tracking.md](references/tracking.md)。
3. **简历分析**：读取简历，评估与目标岗位的匹配度，给出可落地的修改建议。详见 [resume-analysis.md](references/resume-analysis.md)。
4. **岗位分析**：对候选岗位按既定维度评估，输出结论与建议。详见 [job-analysis.md](references/job-analysis.md)。

## 输出要求

- 找岗位：先给出一组最匹配的岗位，再按类型/城市分类列出其余岗位；每项附证据来源与明确建议。
- 岗位分析：结构化结论 + 证据来源 + 明确建议。
- 投递追踪：每次更新后给出变更摘要。
- 简历分析：按优先级列出问题与修改动作。
